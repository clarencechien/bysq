## 0. 一句話任務

用真實歷史資料（不是常態分布參數），為**一位在台灣生活、以新台幣支出的投資人**，找出在累積期與 50 年提領期中，能在「終身實質支出」與「不破產」之間取得最佳權衡的資產配置與提領規則。

**這不是要找一個最佳解，是要畫出 Pareto 前緣，並且誠實標示每一個結論的失效條件。**

---

## 1. 為什麼要重做：前一版模擬的缺陷清單

先前有一版 Python 蒙地卡羅（GK 60/40 vs GK 80/20 vs BYSQ）。**新引擎必須逐項避開以下每一個問題，並在測試中證明已避開。**

| # | 缺陷 | 後果 | 嚴重度 |
|---|---|---|---|
| 1 | 股票／債券／通膨三個隨機源獨立抽樣 | 共變異數被摧毀，股債同跌（2022）永不發生；而股債比正是本研究主題 | 致命 |
| 2 | 通膨與報酬零相關、常態分布 | 1970s 型態的通膨體制不可能出現；Cederburg 主張的「長期真正風險是通膨」在結構上無法被檢驗 | 致命 |
| 3 | 現金水池策略用「當年報酬」決定當年是否動用（前視偏誤） | 白送完美擇時能力給水池策略 | 致命 |
| 4 | 只用「生存率」比較 GK 類策略 | GK 的機制就是拿支出換生存；只計收益不計代價，接近循環論證 | 致命 |
| 5 | 年底提領（`wealth*(1+r) - spending`） | 花掉的錢先享受了一整年複利，系統性高估存活 | 高 |
| 6 | 水池拿零波動的固定利率，債券部位卻有波動 | 同一類資產兩套待遇 | 高 |
| 7 | 回補水池只看漲跌不看水位 | −40% 後的 +5% 年份照樣賣股回補，賣在低點 | 高 |
| 8 | 常態分布報酬 | 無負偏態、無肥尾、壞日子不扎堆 | 高 |
| 9 | 無稅、無費、無匯率 | 標的是海外資產，支出是台幣，這三項都不是零 | 高 |
| 10 | 報名目金額、單一亂數種子、註解與數值差一個數量級 | 可讀性與可信度 | 中 |

## 2. 資料層規格

### 2.1 主引擎（Primary Engine）— 月頻

目標序列，全部**換算為新台幣、以台灣 CPI 平減為實質購買力**：

| 序列 | 來源與接法 |
|---|---|
| 全球股票 | 2008+ 用 VT；1970–2008 用 MSCI World / ACWI 或以 Ken French 國際 developed + emerging 權重合成 |
| 全球債券 | 2007+ 用 BND / BNDW；之前用美國 10 年期公債總報酬（Shiller 或 FRED）+ 國際政府債代理 |
| 短期現金 | 美國 3 個月國庫券；台幣版另取台灣一年期定存利率 |
| 台灣 CPI | 主計總處，1959+ |
| USD/TWD | 1980+（1979 前為固定匯率，不可用） |

**實際可用起點取決於匯率**：約 1980 起，46 年、552 個月。

**接序列的紀律**（沿用先前作法）：
- 每一段接點都要標註來源與方法，寫進 `data/PROVENANCE.md`
- 重疊期間必須對答案：報告月相關係數與逐年差
- 若近似段有偏誤，明確標示偏誤方向（是對策略太客氣還是太嚴苛）

### 2.2 面板引擎（Panel Engine）— 年頻，用於尾端穩健性

主引擎只有 46 年，且是「美國主導的全球股市剛好很成功」的那 46 年。必須有第二個引擎回答：**如果未來像某些非美國家的歷史呢？**

- **Jordà–Schularick–Taylor Macrohistory Database**：18 國、1870–2020，股票／債券／短票報酬 + CPI，免費
- 用途：不是拿來當主結論，是拿來檢驗「主引擎的結論在多少個國家—期間上仍成立」
- 這條線直接對應 Cederburg 那派的論證，也對應「4% 法則在美國 96.7%、在法國 35.2%」那類發現

### 2.3 匯率處理（重要設計決策）

台幣支出 + 海外資產 = 匯率是一層真實風險，不是雜訊。**必須跑三個情境並分別報告**：

- `fx_mode: "historical"` — 用實際 USD/TWD 路徑（與資產報酬同時間軸抽取）
- `fx_mode: "hedged"` — 完全避險，僅扣避險成本（利差）
- `fx_mode: "ppp"` — 匯率長期回歸購買力平價，短期波動保留

**若三個情境的策略排序不一致，這件事本身就是主要發現，必須寫在報告最前面。**

### 2.4 稅務層

台灣現行規則（實作為可關閉的模組，參數externalize 到 JSON）：

- 本國證券資本利得：免稅
- 海外所得：全戶全年合計達 **100 萬**需全數計入基本所得額
- 基本所得額超過 **750 萬**部分，以 **20%** 計算基本稅額，再與一般所得稅額比高者課
- 提領期通常無薪資所得，故多數年份可能不觸及；但再平衡實現大額利得的年份可能跨線
- **注意**：稅法會變，把年度參數放在 `config/tax_tw.json`，並在報告標註「以 2026 年規則為準」

## 3. 引擎規格

### 3.1 抽樣方法

**Stationary block bootstrap（Politis–Romano），幾何分布區塊長度。**

- 平均區塊長度預設 **36 個月**，敏感度測試 `[12, 24, 36, 60, 120]`
- **關鍵**：先合成、再重抽。所有資產 + 通膨 + 匯率在同一個月按權重合成後，只對**時間索引**抽樣。抽到 2008-10，就是所有序列的 2008-10 一起被取用
- 必須有單元測試驗證共變異數保留：重抽序列的股債相關係數應與原始序列在信賴區間內一致

**另外必跑（不可省）**：
- **歷史重疊區間**（非 bootstrap）：所有實際存在的 30/40/50 年重疊窗口。樣本少，但它是唯一沒有任何模型假設的結果
- 兩者結論若不同，以歷史重疊為準來寫警語

### 3.2 排除清單（測試必須驗證）

- 決策只能使用 **t−1 及之前**的資訊。寫一個 `assert_no_lookahead()` 在每個策略上跑
- 提領在**期初**（或按月，若採月頻現金流）
- 所有現金／短債部位使用**同一組隨機利率序列**，不得給任一策略零波動待遇

### 3.3 落地要求（沿用既有系統風格）

- 所有門檻與參數 externalize 到 `config/*.json`，程式碼不硬編數字
- 資料缺漏時 graceful degradation 到 `NO_DATA`，不得靜默補值
- 狀態檔 append-only，每次 run 記錄 seed、config hash、資料版本
- 多 seed（至少 5 組）跑主結果，報告 seed 間離散度

## 4. 策略矩陣

### 4.1 累積期（可選，若時間有限可先做提領期）

- 靜態：60/40、80/20、100/0
- 目標日期式滑翔（線性降股）
- **上升股票滑翔（bond tent）**：退休前 10 年開始堆債，退休後 15 年滑回高股票

累積期輸出的是「退休當下的財富分布」，直接餵給提領期，**不可用固定初始財富**——這一步很重要，因為累積期的結果與提領期的順序風險是相關的。

### 4.2 提領期配置

- 靜態 60/40、80/20、100/0
- 上升股票滑翔（bond tent，續前）
- **現金桶（修正版 BYSQ）**：100% VT + N 年台幣短債桶
  - 觸發規則只能用 t−1 資訊，例如「年初股票部位低於歷史高點 X%」
  - 回補規則必須看**水位**（例如創新高才補滿），不是只看漲跌
  - N 掃描 `[2, 3, 5, 7, 10]`——先前討論指出 2–3 年蓋不住 1966–1982（16 年）或 2000–2009（10 年）

### 4.3 提領規則

- 固定實質（4% 法則基準線）
- **完整 GK（四條規則都要）**：
  - Inflation rule（凍結通膨調整）
  - Capital preservation rule（**砍 10% 實質**，不只是凍結）
  - Prosperity rule（+10%）
  - Portfolio management rule
  - 註：原始 GK 在計畫最後 15 年停用 capital preservation rule，要實作
- Vanguard 動態支出（上下限 +5%/−2.5%）
- VPW / 攤還法（依剩餘年期重算）
- 固定百分比（endowment）

**先前那版把 capital preservation rule 錯寫成只凍結通膨調整——這是必修項。**

## 5. 目標函數與指標

### 5.1 為什麼不能只看生存率

GK 與所有動態規則都是**拿支出換生存**。只量生存率等於只計收益不計代價。一條「活著但實質支出腰斬三十年」的路徑不該與「活著且支出照計畫」同分。

### 5.2 主要指標

以**台幣實質購買力**計，50 年期：

1. **終身實質支出的 5th percentile**（主要目標函數）
2. 終身實質支出中位數
3. 破產率（財富歸零）
4. **支出失敗率**：實質支出低於初始值 70% 且持續 ≥3 年的路徑比例
5. 最大累計實質減支幅度（分布）
6. 期末實質財富分位數（遺贈動機）
7. CRRA 確定等值支出，γ = `[2, 4, 8]`

### 5.3 輸出形式

**畫 Pareto 前緣**：橫軸「終身實質支出中位數」，縱軸「5th percentile 支出」，每個策略是一個點，點的大小表示破產率。這比任何表格都更能說明取捨。

不要報「成功率 95%」這種單一數字。若要報，必須同時報 bootstrap 抽樣誤差與**區塊長度敏感度**——後者通常大得多。

## 6. 預先登記的證偽條件

**在跑之前寫進 `PREREGISTRATION.md`，跑完不得修改。**

| 假說 | 證偽條件 |
|---|---|
| H1：100% VT + 現金桶在 5th-pct 終身支出上優於 60/40 | 若在 `fx_mode: historical` 或 γ=8 下反轉，則 H1 不成立 |
| H2：GK 護欄優於固定實質提領 | 若 GK 的「支出失敗率」高於固定提領的破產率，則護欄只是把破產換成貧窮 |
| H3：現金桶年數 2–3 年足夠 | 若 5 年以上仍持續改善 5th-pct 支出，則 2–3 年不足（預期會被證偽） |
| H4：結論對抽樣方法穩健 | 若區塊長度從 12 改到 120 使策略排序改變，所有結論降級為「方法相依」 |
| H5：主引擎結論可推廣 | 若在 JST 面板上，該結論僅在 <50% 的國家—期間成立，必須在報告首頁標示 |

## 8. 執行順序

1. **先做資料層 + 測試**。資料錯了，後面全錯。`data/build.py` 跑得出來、`PROVENANCE.md` 寫得出來，才往下走
2. **實作 bootstrap + 兩個測試**（no-lookahead、covariance）
3. **只跑一個策略**（固定實質 4%、60/40）對答案：跟文獻已知的美國歷史成功率是否吻合。不吻合就停下來查
4. 展開策略矩陣，先只跑 `fx_mode: hedged`（最單純）
5. 加上匯率三情境與稅務層
6. JST 面板引擎
7. 寫報告

**第 3 步是關卡**。在對得上已知數字之前，不要展開矩陣。

## 9. 給實作者的一句提醒

這個題目最常見的失敗不是程式寫錯，是**指標選錯**。任何最優解落在約束邊界角落的指標，都不是在衡量風險。如果跑出來「某策略在所有維度全面勝出」，第一反應應該是找 bug，不是寫結論。
